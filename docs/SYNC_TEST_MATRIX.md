# Synchronization test matrix

- Status: **Accepted**
- Scope: synchronization behavior, recovery, evidence, and test-harness requirements
- Updated: 2026-08-11

This matrix is the verification contract for [the synchronization specification](SYNC_SPEC.md).
External behavior comes from the [Google Tasks API contract](GOOGLE_TASKS_API_CONTRACT.md),
not from assumptions embedded in a fake. No synchronization implementation exists yet;
every fake capability named below is therefore an implementation requirement.

## Evidence rules

- Tests drive public repository, coordinator, engine, authorization, and adapter ports.
  Source-string assertions and mocks that only return a canned value are forbidden.
- A stateful Google fake models resources and validates requests. It must expose a call
  ledger and deterministic barriers before dispatch, after server commit, before response,
  and before local acknowledgement.
- Tests advance injected wall and monotonic clocks explicitly. They never sleep.
- Backoff jitter comes from a deterministic sequence. Randomized tests print and persist
  their seed on failure and must support shrinking and exact replay.
- Expected durable state is asserted by closing and reopening the store, not merely by
  inspecting an in-memory object.
- A process-death test launches the production persistence path in a child process,
  kills that process at the named barrier, and reopens the real temporary SQLite file
  from a separate process. An injected exception is not process-death evidence.
- `Good`, last verified success, scope completeness, and absence deletion are asserted
  independently. Publication of valid partial data proves none of the other three.
- A live Google probe establishes only adapter contract behavior. Core reconciliation and
  failure tests use the strict fake so every interleaving remains repeatable.

### Notation

`B` is the committed remote base, `L` the projected local state, `R` the state held by
Google/the strict fake, `Dg` desired-state generation *g*, and `A` a durable attempt.
`C`, `S`, and `X` are the content, structure, and lifecycle facets. Times are injected UTC
wall-clock values; deadlines use the injected monotonic clock. “Unchanged outside scope”
means the test also seeds a sibling, child, another list, and another account and compares
their complete before/after state.

## Required test infrastructure

| Capability | Required behavior | Implementation status |
|---|---|---|
| `F-STORE` | Real temporary-file SQLite store with the production schema/transactions; a killable child-process driver; reopen/WAL recovery from a separate process; commit barriers; fail-before/fail-after-commit; unavailable, malformed-schema, and corrupt-file modes. | Missing; required before synchronization implementation can be accepted. |
| `F-GOOGLE` | Stateful strict Tasks server with lists/tasks/tombstones, ETags, server `updated`, pagination, completion cascades, stable-ID moves, opaque positions, request validation, scripted status/body/header outcomes, and a complete call ledger. | Missing; required. |
| `F-BARRIER` | Named deterministic barriers at run phases, page boundaries, request dispatch, server commit, response delivery, and every SQLite transaction boundary. Supports kill/cancel and ordered release. | Missing; required. |
| `F-TIME` | Independently controlled UTC wall clock, monotonic clock, timers, and deterministic full-jitter source; supports wall-clock discontinuities. | Missing; required. |
| `F-AUTH` | Stateful authorization fake for unknown/usable/refreshing/expired/wrong-scope/revoked/terminal states, subject mismatch, interactive cancellation/success, and request rejection after dispatch. | Missing; required. |
| `F-LIFE` | Linux process/window and Android resumed/paused/stopped event driver with explicit cancellation acknowledgement. | Missing; required. |
| `F-CONN` | Connectivity hints for unknown, proven-no-route, and may-have-returned; cannot directly declare Google healthy. | Missing; required. |
| `F-OBS` | Records typed repository streams, `SyncHealth`, user-safe details, diagnostics, run/phase transitions, and request counts without deriving expected values from production code. | Missing; required. |
| `F-MULTI` | Two or three isolated installation stores/coordinators sharing one `F-GOOGLE`, each with its own local IDs and clock. | Missing; required. |
| `F-MODEL` | Reference state machine and command generator with replayable seeds, shrinking, invariant checks after every transition, and bounded quiescence detection. | Missing; required. |
| `F-PROBE` | Opt-in live-adapter runner that verifies an ignored expected Google subject before any Tasks call, fails mismatches with zero Tasks enumeration/mutation, uses disposable unique prefixes, sanitizes records, guarantees cleanup, and verifies zero matches. | A historical probe harness exists outside product code; a subject-guarded Flutter adapter contract runner is still missing. |

`F-GOOGLE` must not silently implement undocumented server behavior. Its defaults are only
documented or currently probed facts. Unknown status codes, malformed success bodies,
pagination races, and auth shapes are injected explicitly. `F-PROBE` is the gate for
promoting any such behavior into the fake.

## Fake capability audit and acceptance gate

The current documentation-only repository has no synchronization test harness. Therefore
all `F-*` entries are missing implementation work, not evidence that can be marked passed.
Before engine code is accepted:

1. `F-STORE`, `F-GOOGLE`, `F-BARRIER`, `F-TIME`, `F-AUTH`, `F-LIFE`, `F-CONN`,
   and `F-OBS` must pass their own qualification tests, including `MOD-005`.
2. Every named run phase and durable transaction boundary must be addressable by a barrier;
   a generic “throw on call N” fake is insufficient.
3. `F-GOOGLE` must reject unsupported requests and expose exact call/page/operation counts.
   It must model partial response delivery separately from server commit.
4. `F-STORE` must exercise SQLite atomicity and reopen behavior. An in-memory map cannot
   provide crash-safety evidence; process-death rows require a killed child process and
   recovery from another process.
5. `F-MULTI` and `F-MODEL` must use the same production ports as deterministic integration
   tests and must not duplicate production reconciliation code as their oracle.
6. `API-006` remains a capability gate for the affected Linux and Android authentication
   slices. `API-009` now admits JSON-null clearing for supported `notes`/`due`, while exact
   stale-source delete fake/recovery behavior remains gated. P10 recurrence-link evidence
   remains outside core synchronization and does not block this matrix.
7. `API-008` must fail closed before any Tasks request when the authenticated subject is
   missing or differs from the ignored expected-subject value.

No wall-clock sleeps, network-dependent default test, source inspection, or expectation-free
“does not throw” test can satisfy an ID in this matrix.
